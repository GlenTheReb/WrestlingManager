# WM-010 — Moveset and learning content

Status: Capability brief; not implementation-ready. Depends on WM-007. Suggested delivery lane: M2.
Reserved branch stem: `feature/wm-010-moveset-library`.

## Player promise

Workers possess recognisable personal repertoires, signatures and finishers; experience, training and
usage can change proficiency without turning the move list into cosmetic biography text.

## System contract

- Owns move catalogue validation, personal repertoire membership, proficiency and learning history.
- Consumes stable worker IDs, body/style context and WM-007 execution needs.
- Emits legal move candidates and dated learning/proficiency changes.
- Presentation intent/contact metadata remains renderer-neutral and optional assets never define moves.

## Planned execution slices

1. Stable move taxonomy and validation for contexts, risks, targets and presentation intents.
2. Coherent generated personal repertoires with signatures/finishers.
3. Proficiency, usage and learning/training rules.
4. Profile/booking inspection plus catalogue and representative-style balance tests.

## Invariants and exclusions

- A move has simulation meaning and legal context; names alone are not content.
- Generated repertoires respect size, background, style and proficiency constraints.
- Learning is dated and bounded; reload cannot grant duplicate progress.
- Do not add animation clips, copyrighted move footage or viewer-specific behavior.

## Decisions before relevant slices

PD-114 must approve taxonomy depth, naming policy, repertoire sizes, learning rates and which move details are
public, scouted or hidden under PD-102.

## Capability exit

The catalogue validates deterministically, workers have coherent distinct movesets and match/finish
execution uses the same canonical repertoire visible in management screens.
