# WM-004 — Expanded match-plan persistence and booking UI

Status: Capability brief; not implementation-ready. Depends on WM-002–003. Suggested delivery lane:
M2. Reserved branch stem: `feature/wm-004-team-booking`.

## Player promise

The booking desk can define teams, slots, entrants, falls/eliminations and results safely without
making the fast singles workflow cumbersome.

## System contract

- Owns the versioned persisted match-plan representation and its edit/validation command surface.
- Consumes rule semantics from WM-001–003; it does not redefine runtime legality.
- Emits one canonical validated plan used by agent advice, start-show and resume.
- WM-009 owns advanced draft/undo/template workflow; WM-005 owns additional stipulation fields.

## Planned execution slices

1. Canonical plan DTO and backup-safe migration with legacy-field removal strategy.
2. Bounded mutation commands with card revisions and validation errors.
3. Accessible team/entrant/result editor retaining identities through reorder/edit operations.
4. Contract generation, integration tests and native save/reload smoke.

## Invariants and exclusions

- There is never a legacy plan and expanded plan acting as competing sources of truth.
- Invalid plans cannot persist partially or reach the simulator.
- UI labels derive from rules; an option cannot appear before its runtime rule exists.
- Do not add unrelated visual redesign or broad booking productivity features.

## Decisions before relevant slices

PD-134 rules H4 and I3 lock progressive disclosure and result authority. The execution ticket must
name mandatory, optional and agent-filled fields for its supported match formats.

## Capability exit

All WM-002–003 structures can be created, edited, saved, reloaded and started through the same plan,
while current singles careers retain their behavior.
