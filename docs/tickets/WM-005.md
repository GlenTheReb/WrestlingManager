# WM-005 — Composable stipulation rules

Status: Capability brief; not implementation-ready. Depends on WM-003–004. Suggested delivery lane:
M2. Reserved branch stem: `feature/wm-005-stipulation-rules`.

## Player promise

Stipulations create genuinely different planning, risk and victory tradeoffs through composable
rules instead of a long selector whose options all simulate the same way.

## System contract

- Owns stable rule catalogues for legal actions/locations, weapons, escape, scoring and victory.
- Consumes participant/team/entry rules and the canonical match plan.
- Emits rule-derived legality, risk, event and report facts used by agents and presentation.
- Content names are independent WM data; implementation uses capabilities, not trademarked formats.

## Planned execution slices

1. Rule-composition schema, compatibility validation and one representative location modifier.
2. Weapon/no-disqualification/table interaction family with safety consequences.
3. Escape/enclosure/ladder objective family.
4. Timed scoring/standing/submission/falls-location family, then combination/property testing.

## Invariants and exclusions

- Every exposed rule changes at least legal planning plus one causal simulation/report behavior.
- Unsupported combinations fail before persistence or show start with an actionable reason.
- Rule IDs remain stable for saves and future custom databases.
- Do not build a separate simulator per display name or attempt the full catalogue in one branch.

## Decisions before relevant slices

PD-111 must approve the initial representative rule set, permitted combinations, safety intensity and product/
audience expectations after PD-105 is resolved.

## Capability exit

Major rule families compose predictably, remain deterministic and influence planning, execution,
safety, crowd response, consequences and reports without duplicated engine paths.
