## Delivered outcome

The old name-only search and capped Ctrl+K overlay are replaced by one persistent full-page Talent
Search. It searches public current worker data, combines structured filters, supports deterministic
two-field sorting and pages 25/50/100 rows. The player can configure columns, compare up to four
workers, save complete views, keep multiple named shortlists and maintain one personal blacklist.
Finder query, page, columns, selection and scroll position survive profile and screen navigation.

Ctrl+K and Talent navigation open the same Finder and focus its text box. Booking deliberately keeps
the older bounded `roster_page` command because it is a small participant picker, not a competing
world-search interface.

## Implemented contracts

- `wm-domain/discovery.rs` owns validated request, range, filter, availability, blacklist, sort,
  result, facet and saved-list DTOs. Requests allow one or two unique sorts, text up to 80 characters,
  valid age/0–100 ranges and pages up to 100.
- Schema 7 / engine 0.6.0 adds `worker_discovery_index`, `worker_saved_views`, `worker_shortlists`,
  membership and blacklist tables. The index is a rebuildable projection; `workers` remains the
  source of truth and `write_worker` refreshes the projection after worker changes. Earlier local
  schema-7 candidates idempotently receive any missing query indexes when opened.
- Search is server-owned. Filtering, sorting, counting and LIMIT/OFFSET paging execute in SQLite;
  Rust hydrates only the selected page. Structured criteria support searchable include/exclude
  choices. Text checks name, nationality, training background, language and biography; bounded name
  typo tolerance supplies an explicit “Close name match” reason. Worker ID is the stable tie-break.
- Current filters cover age, current-style Overall, all six base groups, availability, nationality,
  language, training lineage, Archetype, Primary Discipline, shortlist and blacklist scope. The filter
  icon opens a grouped, searchable drawer; every active criterion is individually removable.
- Saved views persist the full request and visible columns inside the career. List membership changes
  no worker or simulation fact. Membership changes are reversible; deleting a saved view or shortlist
  requires confirmation.
- The desktop uses generated Rust contracts. Zustand owns only working interface state; SQLite owns
  durable views/lists; React Query owns fetched pages.

## Intentional exclusions

- No legacy scalar popularity filter or column. WM-012/024 must first supply the accepted regional
  popularity model.
- No company, contract, storyline, event, history, relationship or profession filters before those
  canonical domains expose safe searchable projections. They register with this framework later.
- No invented aliases, private scouting values or hidden facts. Alias matching begins only when the
  WM-025 Character model owns aliases. The current `Worker.name` is a legacy source field, not proof
  that Person and ring identity are the same.
- No simulation consequences from a shortlist or blacklist, no runtime AI and no client-side
  whole-world filtering.
