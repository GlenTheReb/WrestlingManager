## Outcome and player value

Replace the cramped wrestler overlay with one coherent, role-ready Person hub. The player can answer
who this person is, how they perform, their current state, what happened recently and what supported
action is available without losing the search, booking, news or report context they came from.

## Intentionality answers

- **Player decision:** evaluate, compare, interact with and book around a person using current ability,
  condition, identity, history and relationship evidence.
- **Canonical cause:** existing Worker, ratings, Person identity, Character, relationship, match-report,
  news and show-plan records.
- **Consequence and explanation:** this ticket is primarily a read model; existing interaction and
  Character commands remain the only mutations and retain their recorded outcomes.
- **State layers:** personal facts and relationships remain real-life state; Character is kayfabe;
  layout, icons and summaries are presentation.
- **Reused contract:** extend `WorkerProfile`; do not create a second Person, rating, history or media
  source.
- **Missing information:** omit unfinished domains and use honest in-world empty states only for
  domains whose canonical data exists. Unknown never means zero.
- **Main abuse/failure case:** unbounded history, fabricated cross-domain facts, stale interaction
  writes or losing the originating workspace.
- **Workflow improvement:** one quick reference surface can expand into a dense full hub; tabs and
  grouped actions replace button walls while the underlying workspace stays mounted.
- **Integration:** worker-linked news, shows, Characters and relationships are reachable from the hub;
  close returns to the exact prior client state.

## Included behavior

- A compact quick profile with a clear **Full profile** action and a full-size persistent hub.
- Header with active ring identity, portrait fallback, archetype, contextual Overall, availability,
  age, nationality and current Character/alignment.
- Overview with six rating groups, current condition, style identity, latest form, next booking and a
  bounded worker-news rail.
- Tabs: Overview, Attributes, Character, Career, Matches & Appearances, Relationships, Contract,
  Development and Media. Tabs backed only by existing facts are visible.
- Attribute detail, Discipline fits, repertoire/moveset, personal record, biography, traits and
  existing chronological relationship conversations.
- Bounded enriched appearance rows with show/date, segment kind, participants, result, duration,
  performance dimensions, reasons and show deep-link where supported.
- Bounded worker-linked news and a bounded next-booking projection.
- Organised profile actions that navigate only to working commands or views.
- Persistent profile tab and quick/full mode for the current session; closing preserves the
  originating screen, filters, selection and scroll state.
- Accessible red-to-green value bands with text labels, semantic controls, keyboard operation and
  responsive desktop layout.

## Excluded behavior and stop condition

- No new contract, title, team, stable, training, regional popularity, journalist, social-network,
  role/profession, portrait-pack or protected-move mechanics.
- No fake cards, random values, runtime language model, client-side world scan or universal Overall.
- Stop when every existing profile fact has one coherent destination, bounded projections and focused
  tests pass; do not expand into WM-010, WM-026–028, WM-031–032, WM-036 or WM-041.

## Acceptance criteria

- Opening a person from Talent Search or News first provides useful quick context and can expand to the
  full hub without refetching a second source of truth.
- Closing either mode restores the exact underlying screen and existing Talent Search state.
- Overview, Attributes, Character, Career, Matches & Appearances, Relationships, Contract,
  Development and Media render canonical data or an honest in-world empty state.
- Match history is newest-first and bounded to 30; news is newest-first and bounded to 8; next booking
  returns at most one future segment.
- All six groups, sub-stats and Discipline fits use the accepted contextual labels and value bands.
- Current-style Overall is explicitly labelled as wrestling/style context and popularity stays
  separate.
- No unfinished system is represented as working and no player-facing “not implemented” appears.
- Focused Rust and React tests cover read-model enrichment, quick/full navigation, tabs, empty states
  and accessible labels.
