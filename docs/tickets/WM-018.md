# WM-018 — Regression, balance, performance and soak suite

Status: Continuous capability brief; not a substitute for tests in earlier tickets. Final release
gate depends on WM-015–017 and accepted PD-134 quality/release rules. Reserved branch stem:
`feature/wm-018-quality-gates`.

## Player promise

The released game remains deterministic, responsive, accessible and believable across long careers,
large worlds, upgrades and supported hardware rather than only the developer's current save.

## System contract

- Owns cross-system test matrices, performance/balance budgets, soak harnesses and release thresholds.
- Consumes representative fixtures and invariants produced by every capability.
- Emits reproducible failures with seeds, versions and minimal causal diagnostics.
- Unit and migration tests remain owned by the feature that changes behavior.

## Planned execution slices

1. Published fixture taxonomy and regression/budget policy early.
2. Property tests for money, identity, event and result invariants.
3. Representative season and CPU-world soak with deterministic replay.
4. UI performance, accessibility journeys and release-candidate matrix.

## Invariants and exclusions

- A flaky or non-reproducible failure is investigated, not normalized by retries.
- Performance fixtures are bounded and representative; logs never dump entire worlds by default.
- Balance evidence measures distributions and decisions, not one desired score.
- Do not postpone ordinary feature tests until this capability.

## Decisions before relevant slices

PD-134 rules C3–C4 and X3–X5 lock world, career and performance targets. The execution ticket must
record baseline hardware and representative statistical tolerances before measuring them.

## Capability exit

Published deterministic, migration, balance, performance, accessibility and soak thresholds pass on
the release candidate with actionable failure artifacts.
