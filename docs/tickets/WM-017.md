# WM-017 — Game shell, settings and accessible management workflows

Status: Incremental capability brief; not implementation-ready wholesale. The functional front-door
and settings slice may begin against existing screens; full visual/navigation completion consumes
WM-016 and later stable destinations. Reserved branch stem: `feature/wm-017-management-shell`.

## Player promise

The game opens like a desktop management game: a centred menu, clear Careers and Settings, guided
career creation and coherent navigation that preserves context and works without mouse-only friction.

## System contract

- Owns the main menu, Careers/load flow, global-versus-career settings contract, navigation routes,
  history/back semantics, shortcuts, context menus and command palette.
- Presents career setup by consuming WM-012 world generation, WM-030 player/role creation and WM-041
  database selection; it does not duplicate their canonical records or validation.
- Consumes stable screen identities, entity deep links, draft guards and permission/knowledge rules.
- Emits navigation actions only; it cannot mutate domain state indirectly.
- Search query behavior remains WM-021/039 and visual patterns remain WM-016.

## Planned execution slices

1. Centred Continue/New/Load/Settings/Database & Editor/Credits/Exit menu, Career cards and explicit
   empty/loading/error states; replace platform-like “Save Library” language.
2. Display, Interface, Gameplay, Simulation, Accessibility, Audio and Controls settings with clear
   global/career ownership and durable storage.
3. Quick Start, Guided Setup and Advanced Setup flow consuming WM-012/030/041 previews and validation.
4. Canonical route/entity-link model, Home/Office, Booking, Roster, Talent/Scouting,
   Development/Training, Company, Finances and World hierarchy, and preserved return context.
5. Global actions, command palette/search handoff, dirty-work guards, keyboard/screen-reader semantics
   and compact-layout journey tests.

## Invariants and exclusions

- Navigation never discards unsaved plans silently or triggers a domain action by merely opening.
- Deep links fail safely when entities are deleted, private or no longer known.
- Shortcuts have discoverable labels and do not conflict with text entry or OS conventions.
- Game chrome is not selectable like a webpage; inputs, reports, dialogue and explicitly copyable text
  remain selectable. Settings never silently change career rules or deterministic behavior.
- Do not introduce a second router/state owner or generic links to unimplemented screens.

## Decisions before relevant slices

PD-134 rules A4, B1–B4, C1–C2, D1–D9 and E3–E5 lock shell, settings and navigation direction. Each
execution ticket must specify storage authority, supported destinations and state-restoration journeys.

## Capability exit

Representative high-frequency journeys preserve context and pass keyboard/accessibility checks at
supported layouts with no dead or decorative destinations.
