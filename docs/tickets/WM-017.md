# WM-017 — Navigation and accessible management workflows

Status: Capability brief; not implementation-ready. Built incrementally with proven screens and
completed after WM-016. Reserved branch stem: `feature/wm-017-management-navigation`.

## Player promise

The player can move quickly among Home, Booking, Talent, Company and World, preserve work/context,
use global search and complete common tasks without mouse-only or modal-maze friction.

## System contract

- Owns navigation routes/state, history/back semantics, shortcuts, context menus and command palette.
- Consumes stable screen identities, entity deep links, draft guards and permission/knowledge rules.
- Emits navigation actions only; it cannot mutate domain state indirectly.
- Search query behavior remains WM-021/039 and visual patterns remain WM-016.

## Planned execution slices

1. Canonical route/entity-link model with preserved return context.
2. Home/Booking/Talent/Company/World hierarchy and contextual menus.
3. Command palette/shortcuts, search handoff and dirty-work navigation guards.
4. Keyboard-only, screen-reader semantics and compact-layout journey tests.

## Invariants and exclusions

- Navigation never discards unsaved plans silently or triggers a domain action by merely opening.
- Deep links fail safely when entities are deleted, private or no longer known.
- Shortcuts have discoverable labels and do not conflict with text entry or OS conventions.
- Do not introduce a second router/state owner or generic links to unimplemented screens.

## Decisions before relevant slices

PD-125 must approve top-level information architecture, shortcut catalogue and default return/back behavior.

## Capability exit

Representative high-frequency journeys preserve context and pass keyboard/accessibility checks at
supported layouts with no dead or decorative destinations.
