# WM-020.1 — Canonical wrestler-rating system implementation

Status: Implemented and verified on 10 September 2026; uncommitted pending owner review.
Parent capability: `WM-020`. Branch: `feature/wm-020-wrestler-rating-system`.

## Owner-authorised scope

The original schema-only slice was expanded by the owner to complete every WM-020 slice on one
branch with internal checkpoints. This implementation therefore owns the canonical rating types,
legacy conversion, derivation rules, save migration, simulation adapters, generated contracts and
current roster/profile presentation. It does not implement WM-021 roster filtering, WM-024's full
Football Manager-style profile, or WM-032's training interface and Profession Role ratings.

## Product contract implemented

- Exactly six visible 0–100 groups and the 37 PD-008 sub-stats are stored as canonical facts.
- Group scores are rounded arithmetic means of their sub-stats and are never separately persisted.
- The nine PD-101 Disciplines use the accepted Attribute Fit matrix and
  `55% Attribute Fit + 25% Moveset Readiness + 15% Mastery + 5% Proven Performance`.
- At most two credible Secondary Disciplines enter the accepted 75/25 or 70/20/10 blend.
- Current-style Overall uses the accepted 50/20/20/10 blend plus a bounded -3 to +3 performance
  modifier; popularity, Look, company size and booking position remain excluded.
- Developing, All-Rounder, Approach, Specialisations, curated Archetype naming and Primary-change
  hysteresis follow PD-101. Training-ready evidence adjustments clamp safely to 0–100.
- Wrestlers retain canonical wrestling ability when later used in non-wrestling roles, but WM-032
  remains the authority for shared Person data and independent Profession Role ratings.

## Compatibility and safety

- Save schema advances from 3 to 4 and engine behavior advances from 0.2.0 to 0.3.0.
- Schema 1/2/3 careers retain their historical engine compatibility and migrate through the
  existing verified backup path. A schema-3 source receives an independently readable `.v3.bak`.
- Migration converts stored worker JSON and workers embedded in paused-show snapshots inside one
  immediate transaction. Metadata advances only after every canonical value validates.
- `Rating100` rejects values outside 0–100 and non-integers; nested structs reject unknown or
  missing fields; style profiles require one evidence row per Discipline and unique badges.
- Generated TypeScript declarations remain Rust-owned; the desktop does not maintain a parallel
  rating interface or calculate its own Overall.
- The roster uses `RIN` for Ringcraft, every visible Overall is labelled as style-specific, and
  deterministic Roman ordinals disambiguate generated duplicate names without extra random draws.

## Deliberate behavior change

The old 1–20 worker snapshot and direct field reads are replaced, so the engine-0.2 golden bytes
cannot remain identical. WM-020 explicitly advances the engine contract to 0.3.0 and pins new
snapshot, final-state and event-stream fingerprints. Seeded generation still consumes the same
random draws before deterministic conversion; future engine drift remains test-gated.
