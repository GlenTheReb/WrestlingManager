# WM-015 — Save and compatibility hardening

Status: Continuous capability brief; not one late implementation branch. Every schema ticket owns
its migration; final recovery/compatibility exit follows WM-040. Reserved branch stem:
`feature/wm-015-save-hardening`.

## Player promise

Long careers survive upgrades, interruption and recoverable corruption without silent data loss or
unexplained simulation drift.

## System contract

- Owns global compatibility policy, backup rotation, recovery/repair UX, compaction and diagnostics.
- Consumes migration/version evidence from every domain capability.
- Emits verified load/save/recovery outcomes without exposing raw paths or database internals.
- Individual tickets remain responsible for their own schema and deterministic-version changes.

## Planned execution slices

1. Compatibility policy, fixture archive and per-ticket migration checklist now.
2. Backup rotation, integrity checks and user-controlled recovery.
3. Long-save compaction/performance and cross-version migration matrix.
4. Repair diagnostics and final supported-upgrade rehearsal after world systems stabilize.

## Invariants and exclusions

- A failed or incompatible load cannot partially mutate the original save.
- Backups are created before destructive migration and never overwrite a newer valid revision.
- Engine behavior changes are versioned explicitly; old paused sessions are resumed or rejected safely.
- Do not promise indefinite compatibility before PD-110 defines a release policy.

## Decisions before relevant slices

PD-126 must approve retention/rotation, supported upgrade horizon, repair limits and when deterministic engine
versions remain playable versus migration-only.

## Capability exit

Supported historical fixtures upgrade with verified backups; corruption/conflict paths are safe and
actionable; long careers meet accepted size and performance budgets.
