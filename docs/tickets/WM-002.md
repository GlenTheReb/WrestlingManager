# WM-002 — Tag and trios runtime

Status: Capability brief; not implementation-ready. Depends on WM-001. Suggested delivery lane:
M2. Reserved branch stem: `feature/wm-002-tag-trios`.

## Player promise

Tag and trios matches behave like teams: legal workers, corners, tags, saves, isolation, team control
and coordinated actions matter rather than extra participants acting as passive stamina values.

## System contract

- Owns match-local legal/active slot state, tag eligibility and tag/team-control simulation events.
- Consumes WM-001 participant slots, sides, participation rules, victory rules and booked result.
- Emits deterministic events and report facts used by live views, commentary and consequences.
- Permanent teams, chemistry and membership remain WM-026; this capability uses match-local sides.

## Planned execution slices

1. Runtime state and legal tag transition with pinned singles compatibility.
2. Team-control/isolation and save/coordination behavior using existing worker attributes.
3. Plan validation, live instructions, reports and focused interface exposure.
4. Paused-save migration and deterministic chunk/resume regression evidence.

## Invariants and exclusions

- Only a legal active worker can perform ordinary match actions; substitutions never change identity.
- The booked winner/side remains locked unless a later explicit emergency-result capability exists.
- Do not add elimination, timed entry or more than two competing sides; WM-003 owns those.
- Do not invent permanent tag-team records, entrances or branded match names.

## Decisions before relevant slices

PD-111 must define default tag eligibility, save/interference limits, no-tag team formats and which agent/live
instructions expose legal-worker choices. Record them as accepted product decisions before coding.

## Capability exit

Representative tag and trios matches produce legal, explainable, team-aware event streams and
reports; singles fingerprints and old/paused careers remain valid.
