## Outcome and player value

Replace the current `Roster.tsx` alias of Talent Search with a fast, company-scoped workspace that
answers who is on the player's roster, how they are doing and which real actions are available.
Talent Search remains the separate all-world recruitment tool.

## Intentionality answers

- **Player decision:** identify, compare and act on current company personnel without rebuilding a
  world-search query.
- **Canonical cause:** current save/company membership, WM-025 Character identity and existing
  rating, condition and profile projections.
- **Consequence and explanation:** this is a query/navigation surface; actions route to their owning
  command and history rather than mutating roster facts locally.
- **State layers:** simulation facts and presentation only; it does not create kayfabe or social facts.
- **Reused contract:** WM-021.1 bounded SQL query/paging and WM-025 active identity projections.
- **Missing information:** absent canonical fields/actions are hidden or labelled unknown; they are
  never synthesized.
- **Main failure case:** an unbounded/all-world query or stale company scope leaks unrelated people.
- **Workflow improvement:** quick search stays visible; a filter icon toggles a left criteria pane,
  while active criteria and return state remain understandable.
- **Integration:** profile and compare are preserved; booking, interaction, contract and development
  destinations appear only when their real routes and permissions exist.

## Included behavior

- Dedicated Roster route/component, no longer a re-export of `WorkerFinder`.
- Company-scoped, server-backed, paged query using the current player-company/save boundary.
- Active ring name as the primary label; WM-025 supplies duplicate-name disambiguation.
- Quick text search, sortable visible facts, configurable columns and a toggleable searchable filter
  pane with removable active criteria. Wrestling school is advanced, not prominent.
- Profile/compare and only currently implemented contextual actions.
- Independent query, filter, sort, column, selection, page and navigation-restoration state.
- Loading, empty, error, unknown-value, compact-layout and keyboard-accessible states.

## Excluded behavior and stop condition

- No Global Search, scouting, contract simulation, brand management or speculative roster fields.
- No redesign of Talent Search beyond shared-contract integration.
- No invented brands, roles, contracts, permissions or multi-company employment.
- Stop when Roster is a truthful bounded company workspace and Talent Search remains independent.

## Acceptance criteria

- Roster cannot show an all-world result set or label itself Talent Search.
- Active ring names are primary; duplicate names use WM-025 disambiguation.
- Search/filter/sort/page execute through a bounded backend query on a large fixture.
- Visible sortable columns expose keyboard-operable direction and secondary-sort state.
- The filter button toggles a left pane; applied criteria remain visible/removable when closed.
- Profile round trips restore Roster state independently from Talent Search.
- Every visible action has a real permitted route/command.
- Existing careers and Talent Search remain compatible; generated contracts are regenerated.
