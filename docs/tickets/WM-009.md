# WM-009 — Advanced booking workflow

Status: Capability brief; not implementation-ready. Depends on WM-004 and WM-007. Suggested delivery
lane: M2. Reserved branch stem: `feature/wm-009-booking-workflow`.

## Player promise

The player can iterate on a card safely and quickly through persistent drafts, recovery, card-wide
undo/redo, templates and an advanced timeline without losing work or maintaining duplicate plans.

## System contract

- Owns draft lifecycle, edit history/revisions, template instances and booking-workspace state.
- Consumes the canonical match/angle plans and validation commands.
- Emits only validated plan mutations; simulator and official history never consume UI-only drafts.
- Navigation/close protection integrates with the existing Exit guard.

## Planned execution slices

1. Versioned draft/autosave/recovery domain and persistence.
2. Card-wide command history with bounded undo/redo and conflict behavior.
3. Advanced timeline, duplicate/reorder/drag operations and keyboard interaction.
4. User templates and suggestions-only agent review with native recovery smoke.
5. Pre-match participant sign-off, contingency editing and a persistent Live Direction panel handoff
   without creating a second match plan.

## Invariants and exclusions

- Recovery never overwrites a newer accepted revision and is always attributable.
- Quick and advanced modes edit the same plan; there is no shadow UI model.
- Leaving, closing or crashing has explicit behavior for dirty drafts.
- Do not redesign unrelated company screens or add collaborative/cloud editing.
- The advanced workspace follows the shared interface/integration rules: the running order remains
  central, while one contextual Reference Drawer exposes the relevant roster, teams, titles and
  storylines without scattering lookup buttons or losing the active booking draft.
- Worker concerns, negotiated alternatives and accepted contingencies remain attached to the canonical
  plan; reopening or undoing a draft cannot fabricate acknowledgement.

## Decisions before relevant slices

PD-134 rules H10–H11 lock autosave, recovery, undo and template behavior. The execution ticket must
specify cadence, retention and transaction boundaries before coding.

## Capability exit

Complex cards survive edit/navigation/restart scenarios without data loss, stale overwrite or
different results between quick and advanced editing paths.
